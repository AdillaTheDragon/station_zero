# Архитектурный проект «Станция Ноль»

## 1. Общая идея

Архитектура намеренно простая. Проект не разбит на большое количество классов и систем, потому что игра учебная и её код должен быть легко объяснить.

В `src/` находятся только три файла:

- `main.cpp` — запускает игру;
- `game.h` — структуры данных и класс `Game`;
- `game.cpp` — загрузка данных и вся основная игровая логика.

## 2. Структуры данных

### Item

Хранит информацию о предмете:

```cpp
struct Item {
  std::string id;
  std::string name;
  std::string command_name;
  std::string type;
  int value;
  std::string description;
};
```

### Enemy

Хранит характеристики врага:

```cpp
struct Enemy {
  std::string id;
  std::string name;
  int hp;
  int damage;
  std::string description;
  bool boss;
};
```

### Room

Хранит комнату, четыре возможных выхода, предметы и врага.

У комнаты также есть `enemy_hp` и `enemy_defeated`. Поэтому отдельная структура состояния мира не нужна.

## 3. Класс Game

`Game` хранит всё состояние текущего прохождения:

- здоровье игрока;
- текущую комнату;
- инвентарь;
- текущее оружие;
- список комнат;
- список предметов;
- список врагов;
- несколько логических флагов (`power_on_`, `lockdown_off_`, `warden_defeated_`).

Также `Game` выполняет почти всю логику игры.

Основные функции:

```text
Load()             загрузить CSV
Run()              главный цикл
ShowHelp()         показать команды
ShowRoom()         показать комнату
ShowMap()          показать карту станции
ExecuteCommand()   определить введённую команду
Move()             перемещение
Take()             подбор предмета
Use()              использование предмета
Attack()           бой
CheckVictory()     проверка победы
```

## 4. Обработка команд

Отдельного `CommandParser` нет.

Сначала короткая команда заменяется на полную обычными `if`. Например, `n` превращается в `north`, а `a` — в `attack`. Для предметов `t_` превращается в `take_`, а `u_` — в `use_`. После этого игра работает только с полными названиями команд.

`Game::ExecuteCommand()` получает строку и последовательно проверяет её обычными `if`:

```cpp
if (command == "map") {
  ShowMap();
  return;
}

if (command == "help") {
  ShowHelp();
  return;
}

if (command == "north" || command == "south" ||
    command == "east" || command == "west") {
  Move(command);
  return;
}
```

Команды предметов проверяются по началу строки:

```cpp
if (command.find("take_") == 0) {
  Take(command.substr(5));
  return;
}
```

Это проще отдельной системы команд.

## 5. Основной игровой цикл

`Run()` работает следующим образом:

1. показать вступление;
2. показать стартовую комнату;
3. прочитать строку из консоли;
4. передать её в `ExecuteCommand()`;
5. выполнить команду;
6. повторять цикл, пока игра не закончится.

## 6. Перемещение

Комната хранит четыре строки:

```text
north
south
east
west
```

Если строка пустая, прохода в эту сторону нет.

Некоторые сюжетные ограничения проверяются прямо в `Move()`. Например, если реактор не включён, проход дальше закрыт.

Отдельный файл или класс для замков не используется.

## 7. Бой

Бой находится прямо в `Game::Attack()`.

Алгоритм:

1. найти врага в текущей комнате;
2. вычесть урон оружия из здоровья врага;
3. если враг погиб — отметить его побеждённым;
4. если враг жив — вычесть его урон из здоровья игрока;
5. если здоровье игрока стало 0 — закончить игру.

Специальных атак и отдельного класса боя нет.

## 8. Предметы

`take_<item>` ищет предмет в текущей комнате.

`use_<item>` ищет предмет в инвентаре.

Аптечка лечит игрока. Предохранитель запускает реактор. Токен снимает блокировку. Ключевые предметы для дверей проверяются автоматически.

## 9. Внешние файлы

Используются четыре CSV-файла:

- `rooms.csv` — комнаты, выходы, предметы и размещение врагов;
- `items.csv` — предметы;
- `enemies.csv` — враги;
- `ui.csv` — вступление, финал и несколько сообщений.

CSV используют `;` как разделитель. Для чтения не нужен отдельный класс: код загрузки находится прямо в `Game`.

## 10. Защита от неправильного ввода

Перед выполнением команда проверяется:

- удаляются случайные пробелы по краям;
- английские заглавные буквы переводятся в строчные;
- пустая команда отклоняется;
- команда с пробелами внутри отклоняется;
- неизвестная команда выводит подсказку `help`;
- предмет проверяется перед подбором или использованием;
- нельзя уйти от живого врага;
- нельзя пройти через закрытый сюжетный проход.

## 11. Почему архитектура такая простая

Проект небольшой, поэтому намеренно не применяются отдельные классы для каждой подсистемы. Это увеличило бы количество файлов и связей между ними, но почти не дало бы пользы для игры такого размера.

Главная цель архитектуры — чтобы состояние и игровой цикл были понятны при чтении кода.
